# The catalogue of mutations: one entry per line, five fields separated by TAB.
#
#   id <TAB> file to mutate <TAB> exact text to replace <TAB> text that replaces it
#        <TAB> tests of tests/ that must fail when the mutation is applied
#
# The text to replace has to appear EXACTLY ONCE in the file: a text that appears
# nowhere changes nothing and proves nothing, and one that appears twice is
# ambiguous. The runner refuses both, and so does the coverage check, so an inert
# entry cannot sit in this file unnoticed. A text holds no TAB: the line carries
# exactly four, and a fifth would move every field after it. The text of a shell
# guard therefore starts after the indentation, never inside it.
#
# A mutation removes the whole refusal, not only its exit: a guard that still
# prints its message is often refused again by the next one, and a survivor of that
# kind says nothing. In Python a call of fail() becomes `pass`, never a print that
# would keep the message.
#
# The tests named by an entry are the ones that went red when it was applied. A
# suite that fails in a copy of the tree without any mutation is excluded by the
# runner: it fails there whatever the mutant is, and it would count as a kill that
# never happened.
#
# THE SUITES LEFT OUT, AND WHY
#
# On the machine this catalogue was measured on (2026-11-21), one:
#
#   tests/release/release-signing-mldsa.test.sh
#       Makes and verifies real ML-DSA-65 signatures, which needs cryptography
#       50.0.2, and python3-cryptography 46.0.5 there has no ML-DSA. It fails
#       before it reaches a guard, so no entry names it, and the two guards of
#       verify-sig.py only it reaches are in tests/mutation/exemptions.txt.
#
# Every entry below was measured there: with the mutation applied, each suite it
# names goes red, and with the tree unmutated every suite that can run there passes.
#
# THE GUARDS THAT ARE NOT IN THIS CATALOGUE
#
# A guard with no entry here is not measured by the sweep, so every refusal of the
# scripts under scripts/ and .github/scripts/ and of the run: blocks of every
# workflow has an entry, or a line in tests/mutation/exemptions.txt that says why it
# has none. scripts/quality/check-mutation-coverage.sh fails a pull request that
# leaves one with neither. scripts/build/ is held to the same, and a test for one of
# its guards uses fakes around the script, never a change to it: a change there
# publishes a new release.
#
# Run: tests/mutation/run-mutations.sh [--list] [<id>...]
