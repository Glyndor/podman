# suite-scope.txt -- which paths can change each suite's verdict.
#
# A pull request that touches none of the paths listed for a suite cannot change
# what that suite concludes, so the suite does not have to run to learn what it
# already knows. The decision is made by scripts/quality/scope/ci-job-scope.sh, in
# its `suites` mode, and the job and its required check `test` report exactly as
# before.
#
# WHY IT IS SAFE
#
#   * It fails open, in every direction. A suite with no entry here always runs. A
#     suite whose entry has no pattern is refused. A diff that cannot be read, a
#     rename, a copy, a type change, a checkout that is not the merge commit and a
#     map that cannot be parsed run every suite. A wrong skip lets a change merge
#     untested; a wrong run costs seconds, and the asymmetry decides every
#     borderline case in favour of running.
#
#   * The decision is taken with the resolver and this map as they are in the BASE
#     commit, not as the pull request ships them, so a pull request that rewrites
#     the map or the resolver to narrow its own scope gets the full set instead.
#
#   * What every suite stands on runs every suite, by a rule of ci-job-scope.sh
#     and not by an entry: the workflows, this folder and its suites, anything
#     under tests/ that is not a suite, and what Python can import from the root.
#     A suite added below later cannot forget it.
#
#   * The names of the suites here are the paths the step of tests.yml runs, so the
#     step still finds every suite and tests/workflows/policy/tests-run-every-suite.test.sh
#     still sees a complete list. Only the decision to EXECUTE a suite changes.
#
# HOW THE ENTRIES WERE DERIVED
#
# Each suite was run under strace and every file of the repository it opened or
# listed has to be covered; the sets were then widened to the folder that holds
# them, because the next change there may be the one it reads. A suite that walks
# the tree (`find`, `git ls-files`) depends on the whole tree by name, so its entry
# is `**`. tests/quality/scope/suite-scope-reads.test.sh reads the text of each
# suite and fails on a file it reaches that the entry does not cover; it also asks
# for a path a suite or a step it runs only names, so a few entries are wider than
# what the suite opens.
#
# PATTERN SYNTAX
#
#   *   matches within one path segment.
#   ?   matches one character within one path segment.
#   **  matches any number of segments, including none.
#   A bare path matches that path exactly.
#
# HOW TO EXTEND IT
#
# A new suite arrives without an entry, so it always runs until somebody writes
# one. When you add an entry, measure it the way these were measured:
# `strace -f -y -e trace=%file bash <suite>`.
#
# ---------------------------------------------------------------------------
